# 技术规范草案

版本：0.2｜2026-10-30｜首选技术路线已确认；具体实现设计仍需验证。

## 1. 架构选择

已确认首选路线：Swift + SwiftUI 原生 iOS，云端 Mac 构建，Windows 免费签名安装。建议最低 iOS 18，首要实机 iPhone 14。采用系统 AVFoundation 录音与播放、SwiftData 本地记录、应用文件目录保存资源；课程结构使用版本化 JSON。

理由：离线中英任意文本翻译为硬需求，优先验证 Apple Translation framework 的设备端翻译。Apple 官方说明 TranslationSession 使用设备端模型，与系统翻译共享已下载资源。这里使用基础 Translation API，不把新版 Apple Intelligence 功能作为 iPhone 14 的前提。

用户已接受原生框架，但这不等于已实测成功。最低系统与所调用 API 可用性须逐项核对，禁止误用只在更新系统存在的接口。翻译、麦克风、播放和免费签名组合必须先实机验证。

备选：React Native 配合原生翻译模块，但增加桥接维护；PWA 在离线模型内存、存储与性能未验证前不作为最终首选；单纯套壳 HTML 不自动获得系统离线翻译能力。

## 2. 模块与边界

- Learning：课程编排、计划、步骤状态、复习。
- Audio：录音、播放、暂停、重复、音频会话和中断恢复。
- Conversation：任务状态、录音提交、转写确认、AI 轮次和总结。
- Assessment：评分请求、厂商结果映射、中文建议。
- Translation：语言可用性检查、系统资源准备、离线文本翻译。
- Resources：课程清单、资源下载、校验、版本与空间管理。
- Persistence：数据访问、迁移、导入导出。
- Configuration：设备访问凭据、服务能力、管理员入口。

业务层不直接依赖厂商 SDK；通过适配接口调用。音频结果、评分结果保留 provider 和 model 版本，方便排查。

## 3. 服务端建议

轻量 HTTPS 服务，TypeScript、Node.js 当前受支持的 LTS 版本，容器或托管服务部署；具体云平台及运行时版本开发前确定。5～10 人初期不引入微服务、消息队列或复杂集群。

云端负责保管厂商密钥、设备邀请和撤销、配额、模型适配与管理员配置。学习进度仍只在本机，不默认上传。后端可使用托管数据库保存设备凭据摘要、配置版本及用量；具体数据库随部署平台确定。

建议路由契约：

- POST /v1/devices/redeem：一次性邀请换取设备令牌；邀请有失效时间与次数上限。
- GET /v1/capabilities：返回服务是否已配置、支持能力及配置版本，不返回密钥。
- POST /v1/transcriptions：提交音频，返回识别文本、语言和请求标识。
- POST /v1/conversation/turn：发送 taskId、sessionId、轮次及受限长度的上下文，返回 AI 文本、角色和任务状态。
- POST /v1/speech：提交需朗读文本及音色，返回短期音频地址或音频流。
- POST /v1/assessments：提交 referenceText 与录音，返回统一评分结构。
- POST /v1/conversation/summary：生成任务总结和建议复习项。
- 管理路由：独立认证，管理配置、邀请、设备撤销及用量，不与普通设备令牌共用权限。

通用错误：权限失效、超额、参数无效、音频无效、超时、厂商不可用；带 requestId，用户提示为中文。普通用户不能指定任意上游 URL，避免后台成为开放代理。

## 4. 模型配置与语音链路

初期候选：通义千问或 DeepSeek 负责对话和解释；百炼 ASR 负责转写、CosyVoice 或 Qwen-TTS 负责合成；Azure Speech 负责跟读评测。尚未开通账号、试听或验证网络地区。

按住录音 → 上传 ASR → 转写 → 对话模型 → TTS → 播放。这个分段链路便于替换服务、显示文字和诊断，不以实时多模态模型作为首版必要前提。

对话使用短回答、明确角色、有限任务与难度；用户语音及转写作为学习输入，不可改变系统角色或后台配置。服务端限制录音长度、文本长度和上下文预算。超时重试有次数上限；避免无限生成。

配置逻辑结构：schemaVersion、provider、endpoint、model、region、voice、timeout、capabilities、budget。对话、ASR、TTS、assessment 各自独立配置。密钥使用服务端环境变量或 Secret 引用，不写进仓库、IPA、导出备份、二维码或手机明文配置。

评分输出：overall、accuracy、fluency、completeness（可选）、words、feedback、provider、modelVersion。缺失分项为 unavailable，不按 0 分展示；不同服务商分数不宣称可直接比较。不要求启用额外计费的韵律评分。

## 5. 离线设计

优先通过系统语言可用性检查区分：不支持、支持但未下载、已安装。应用内引导下载中文与英文；不能只因网络断开就认为资源已准备。

文本翻译全程在设备端；不静默转到在线模型。翻译失败给出原因与重试提示。翻译历史建议默认只在本地保存最近记录，并可清空。

课程包包含 manifest、课程 JSON、音频清单、内容版本、字节数和文件摘要。下载到临时目录、校验后原子替换；损坏或中断不得把部分包标为完成。用户学习记录引用稳定内容 ID，升级课程不清空进度。

下载包使用持久文件目录，不只依赖可清理缓存；仍需处理系统存储不足及文件意外丢失。系统翻译资源可用性每次准备翻译时重新检查。音频使用本地路径，飞行模式重启 App 后仍需可用。

离线语音增强：后续评估系统设备端识别与已下载系统音色；若某设备不支持离线识别，保留文本输入，不能调用云服务冒充离线。

## 6. 数据结构

- Scenario：id、标题、排序。
- Lesson：id、scenarioId、version、词句 ID、示范对话、taskId。
- Expression：id、英文、中文、解释、音频资源 ID。
- Task：id、角色、目标、起始语、完成条件、建议轮数。
- Progress：lessonId、当前步骤、完成状态、最近学习时间、累计主动学习秒数。
- ReviewItem：expressionId、原因、自评、下次复习时间、复习次数。
- AssessmentAttempt：id、referenceId、时间、评分、问题词、provider、录音路径。
- Recording：id、所属练习、路径、时长、是否收藏。
- Download：包 ID、版本、状态、校验结果、字节数。
- Conversation：本地 sessionId、taskId、轮次、文本和可选本地音频。

建议复习规则：不会次日复习，模糊 3 天，会了 7 天；阈值与间隔可调整。评分低于候选阈值时提示收录问题词，允许用户移除。建议同一练习只保留最近一次未收藏录音；收藏录音不被覆盖。

## 7. 备份与迁移

导出包含 schemaVersion、导出时间、课程版本、学习数据；已确认默认仅含学习记录，可选打包收藏录音，必须在导出前展示范围。排除厂商密钥、设备令牌和管理员凭据。

导入先校验格式、版本、大小与引用 ID，预览后合并；建议以稳定 ID 去重，时间较新的用户状态优先，操作前保留本地回滚备份。不覆盖另一人的进度而不提示。旧内容缺失时保留可恢复的数据并说明。

## 8. 安全、权限与隐私

麦克风仅在首次录音前申请，拒绝后文字和离线翻译仍可用。录音被中断时停止并提示。提交在线识别或评分前明确会发送录音到云服务。

建议云端录音仅短时处理，目标处理后删除，临时文件最长保留 24 小时；实际厂商保留策略须逐家核查后写进交付隐私说明，不能承诺厂商零留存。普通日志不记录录音、密钥、完整对话或个人证件信息。

设备令牌存系统 Keychain；服务端只存可撤销的凭据摘要；管理员独立认证。即使不注册学习账号，管理员也必须有认证。单设备速率、日额度与总预算都应可配置。

## 9. 性能建议与构建

性能目标待实机建立基线：正常设备冷启动约 3 秒内进入首页；已准备模型的短文本翻译建议 5 秒内出结果；短录音松手后正常网络约 8 秒内开始回答。网络和厂商延迟需单独记录，不把建议目标写成实测结果。

Windows 负责编辑、版本管理和管理云构建。macOS + Xcode 生成真机 arm64 App，打包待重签 IPA；再交给 Windows 工具免费签名。固定并记录实际 Xcode、SDK 和 runner 版本，不长期使用不受控的 latest。

未签名构建与重签属于待验证交付链，不直接套用要求付费开发者账号的 EAS 自动签名流程。免费签名不能被认为支持所有 entitlement；如翻译或其他能力受限，暂停并重新评估方案，不擅自转付费账号。

## 10. 月度预算控制

已确认阈值：项目全体用户合计每月 100 元提醒、200 元停止新云端请求。建议按 Asia/Shanghai 自然月计量，币种人民币；外币服务保存原币金额、换算依据和时间。

服务端统一记录 ASR、对话输入输出、TTS、评分及重试的用量。执行调用前按单次最大音频、文本和 token 限额估算费用并预占；同一预算的并发预占必须原子执行。已结算费用加在途预占加拟提交请求超过 200 元时拒绝新请求，不等厂商账单更新后才拦截。

100 元提醒在管理员界面持久显示，每个自然月仅记录一次跨阈值事件；不默认向外发送通知。调用后按实际可得用量结算并释放多余预占；费用未知时暂保留预占，避免失败重试重复消费。幂等请求需避免重复提交和重复扣账。

达到上限后暂停新云端请求，包括后续对话轮次、识别、评分、语音生成和自动重试；一轮分多次调用时逐次检查，允许保留已完成文本并说明语音未生成的原因。不影响本地数据、已下载内容和设备端翻译。

总费用视图将托管、构建、存储、流量和厂商账单调整单独列出；固定费用并非拦截模型请求即可停止。月初开始新账期，旧月在途调用费用归属保持一致。跨阈值、并发、重试、月底跨月与本地功能可用性均需验收。

应用账本属于预估和用量控制；厂商最低计费单位、价格调整和账单延迟可能造成差异，不承诺全部费用绝对不超过 200 元。实际可用请求额度需在样例课后校准，不能因成本不足自动提高阈值。
