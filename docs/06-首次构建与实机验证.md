## 2. 云端第一次构建

1. 在你控制的 GitHub 账号下创建私有仓库，仓库名可用 `travel-english`。空仓库即可，不必预建 README。
2. 上传本项目源码。必须包括隐藏目录 `.github/workflows`，否则不会出现 Actions 工作流；不要上传 `build`、生成的工程、账号密码或证书。
3. 打开仓库 Actions，按页面提示启用工作流，选择 **iOS validation IPA** → **Run workflow**。工作流仅手动触发，不会每次保存就消耗云构建额度。
4. 首次运行前检查 GitHub 账号的 Actions 额度和消费限制。私有仓库 macOS 构建不承诺免费；本项目 100／200 元阈值用于未来应用云端请求控制，不会自动控制 GitHub 构建账单。
5. 成功后，在该次运行底部下载 `TravelEnglish-validation-运行编号` 产物，解压得到 `TravelEnglish-unsigned.ipa`、SHA256 文件、构建环境和编译日志。
6. 失败时下载同一产物中的日志，优先查看失败步骤，不要把构建失败当成签名失败。首跑失败是可能的，需要依据真实 Xcode 错误修正。

候选环境固定为 `macos-26`、`/Applications/Xcode_26.2.app` 和 XcodeGen 2.46.0。镜像更新若移除对应 Xcode，环境检查会失败；届时明确选定新版本并记录变更，不静默切到最新版本。[GitHub runner 环境](https://github.com/actions/runner-images)、[XcodeGen](https://github.com/yonaskolb/XcodeGen)

## 3. Windows 签名安装

使用 [开发与安装手册](03-开发与安装手册.md) 中的 Sideloadly 流程。选择该未签名 IPA，由手机所有者填写自己的 Apple 账号并完成认证。首次可以先只安装到本人的 iPhone 14，暂不让全部亲友重复操作。

当前应用标识为 `local.travelenglish.app`；正式维护时保持所选签名账号与工具使用的应用标识稳定，避免重复安装或数据容器变化。系统若要求信任开发者或开启开发者模式，按提示完成。

该版本没有麦克风请求，因为尚未实现录音；无须提前授权任何云模型账号。安装失败保留错误文本，移除其中的账号信息后反馈。

## 4. G2 验证步骤

1. 联网打开应用，选“中文 → 英文”，点击“准备当前方向的翻译资源”，同意系统资源下载。
2. 点击“检查资源状态”，确认显示已安装；切换“英文 → 中文”并完成同样检查，缺少资源则继续准备。
3. 先联网输入一句新句子，确认流程运行；这个结果不算离线验收。
4. 开启飞行模式，并单独确认 Wi-Fi 已关闭；强制退出应用后重新打开。
5. 输入未出现在课程或先前测试中的中文，翻译成英文。再切换方向，输入新的英文并翻译成中文。
6. 记录译文、耗时、具体机型、iOS 版本、应用版本与当时是否完全断网。不以状态标签“已安装”单独证明离线可用。
7. 如果不能完成，保留错误信息；不可用系统翻译 App 或预存句库替代验收。

建议初步例句（仅为人工输入测试，不预存译文）：

- 我们有三个人，想预订明天晚上七点的桌位。
- 请不要放花生，我对花生过敏。
- 我预订了两个晚上，但确认邮件上只显示一个晚上。
- Could you tell me which platform the last train leaves from?
- I paid in cash, but I haven't received my change yet.
- Does the rental price include insurance, or is it charged separately?

初步通路成功后，再按 [验收文档](05-验收与待决策.md) 扩展为每个方向至少 20 句的正式检查，并验证签名刷新。不能在这里提前标记为通过。
